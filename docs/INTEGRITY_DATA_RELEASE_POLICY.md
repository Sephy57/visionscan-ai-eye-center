# VisionScan integrity data release policy

This document describes the read-only classification and future-write boundary
for the local SQLite research workspace. It contains no patient text.

## Current evidence

The FK orphan report found 5,263 unresolved references:

| Relation | Count | Classification | Safe automatic repair |
| --- | ---: | --- | --- |
| `documents.study_id -> studies` | 5,260 | `LEGACY_DETACHED_DOCUMENT` | No |
| `analyses.study_id -> studies` | 2 | `LEGACY_DETACHED_ANALYSIS` | No |
| `jobs.study_id -> studies` | 1 | `LEGACY_DETACHED_JOB` | No |

All 5,260 document children are logically deleted and have test/development
origin markers. The two analyses are detached derivative pairs with no study
parent. The job is terminal (`COMPLETED`) with no study parent. No deterministic
identifier mapping, trusted replacement parent, or tenant-preserving evidence
exists, so no row is relinked. The report is generated by:

```text
npm run fk:orphans
```

The generated report is
`docs/generated/fk-orphan-report.json`. It records only relationship metadata,
status/lifecycle evidence, and opaque application identifiers; it never emits
payload clinical text.

The current source reconciliation snapshot contains 235 active unresolved
source dependencies (233 study originals and 2 detached analyses) and 55
historical findings (30 deleted-study originals and 25 deleted-report exports).
Missing active source bytes are represented as unavailable; no bytes are
reconstructed. The adjudication record is augmented with `active_or_legacy`,
`source_classification`, `release_impact`, and PHI-minimizing evidence fields.

## Release gate

Run:

```text
npm run release:data-check
```

This command is read-only and writes
`docs/generated/release-data-check.json`. It reports active and legacy source
counts, active and legacy FK orphan counts, cross-tenant references, hash
mismatches, and preserved quarantine files. It exits non-zero when active
unresolved data, active FK orphans, cross-tenant references, or hash
mismatches remain. Historical legacy findings are visible but do not by
themselves fail the active-data gate.

The observed release-data result is:

```text

legacy_unresolved_sources=55
active_fk_orphan_count=0
legacy_orphan_count=5263
cross_tenant_count=0
hash_mismatch_count=0
quarantine_count=81
status=BLOCKERS_REMAIN
```

## Phased FK strategy

1. **Future-write enforcement (active):** SQLite application writes reject a
   new `documents`, `analyses`, or `jobs` row whose `study_id` is absent. This
   guard runs inside the transaction before payload publication and preserves
   tenant checks.
2. **Evidence-backed legacy repair (not applied):** only an exact immutable
   hash plus patient/tenant/provenance agreement may support relinking. A
   filename, timestamp, nearest study, or inferred identity is insufficient.
3. **Direct FK migration (deferred):** direct constraints remain unsafe until
   the legacy rows are explicitly archived/re-associated and a fresh preflight
   reports zero unresolved active relationships.
4. **Legacy isolation:** detached rows remain retained for audit but cannot be
   reached through an active study workflow. Authorized review is required for
   any future re-association.

Tests in `tests/future-write-integrity.test.ts` prove missing-study document,
analysis, and job writes fail closed; the same test also proves an unavailable
active source cannot enter analysis/replay.
